# Lean Loken: Supabase backend

What's here:

| Path | What it is |
|---|---|
| `migrations/0001_init.sql` | Tables `docs`, `push_subs`, `push_log` and `ll_config` with RLS, a generated CRON secret and `ll_cron_secret()`, Realtime for `docs`, Vault secrets and the pg_cron job (every 5 min). It is idempotent, so you can paste it into the SQL editor and run it again safely. |
| `functions/notify/index.ts` | The Edge Function. The cron job calls it to send due reminders. The app also calls it with `{test:true}` to send a test push. |
| `functions/notify/schedule.js` | **Generated** by `python3 pwa/build-schedule.py` from `app/js`. It holds the same program and timeline logic as the app. Rebuild it and redeploy whenever the program logic changes. |
| `test/` | Tests: `schedule.test.mjs` (node), `sql-idempotency.mjs` (PGlite) and `e2e/run.sh` (Deno with a mock backend). |

**No secrets are set by hand.** The CRON secret is generated in Postgres (Vault). The function reads it via `rpc('ll_cron_secret')`, which only service_role can execute. The VAPID key pair is generated by the function on first need and stored in `public.ll_config` (service_role only). The app gets the public key from `GET .../functions/v1/notify?vapid=1`.

Project: `ramjgwvkuiylwgxspvyl`. Function URL: `https://ramjgwvkuiylwgxspvyl.supabase.co/functions/v1/notify`.

## Deploy checklist (Supabase dashboard)

### 1. Create the project
1. Go to <https://supabase.com/dashboard>, click **New project** and name it `lean-loken`. Pick a region near you (e.g. *West US (North California)*) and save the database password in your password manager.
2. When the project is ready, open **Project Settings → API** (or **Connect**) and copy two values:
   - **Project URL**: `https://ramjgwvkuiylwgxspvyl.supabase.co` (ref `ramjgwvkuiylwgxspvyl`; it is already baked into the SQL).
   - **anon public** key (the publishable key).
   Both go into the PWA's `config.js`. They are public by design, because RLS protects the data.

### 2. Run the SQL
1. Go to **SQL Editor → New query**.
2. Paste **all** of `migrations/0001_init.sql` and click **Run**. The result should be "Success". The final `select cron.schedule(...)` returns a job id.
3. Check the results:
   - **Table Editor** lists `docs`, `push_subs` and `push_log`, each with a "RLS enabled" badge.
   - **Database → Publications → supabase_realtime** includes `docs`.
   - **Integrations → Cron** (or `select * from cron.job;`) lists `lean-loken-notify` with the schedule `*/5 * * * *`.

   Until the function is deployed (step 5), the job's calls return 404. That's harmless.

### 3. Auth: 6-digit email code (OTP), not magic links
1. Open **Authentication → Sign In / Providers → Email** and set:
   - **Enable Email provider**: ON
   - **Confirm email**: ON. This is fine because the code confirms the address.
   - **Email OTP Length**: **6**. The app's code input expects 6 digits.
   - **Email OTP Expiration**: 600 s or more, so you have time to switch apps.
   - Click **Save**.
2. Open **Authentication → Emails → Templates**. Edit both **Magic Link** and **Confirm signup**. A brand-new email gets the "Confirm signup" email on its first sign-in, so both templates must show the code.

   **Magic Link**: Subject `Your Lean Loken code: {{ .Token }}`
   ```html
   <h2>Your Lean Loken sign-in code</h2>
   <p>Enter this code in the app:</p>
   <p style="font-size:32px;font-weight:700;letter-spacing:6px;font-family:monospace">{{ .Token }}</p>
   <p>It expires in 10 minutes. If you didn't try to sign in, ignore this email.</p>
   ```
   **Confirm signup**: Subject `Your Lean Loken code: {{ .Token }}`
   ```html
   <h2>Welcome to Lean Loken</h2>
   <p>Enter this code in the app to finish signing in:</p>
   <p style="font-size:32px;font-weight:700;letter-spacing:6px;font-family:monospace">{{ .Token }}</p>
   <p>It expires in 10 minutes.</p>
   ```
   Leave `{{ .ConfirmationURL }}` out on purpose. On iOS a link opens Safari, not the installed app.
3. The built-in email sender is rate-limited to a few emails per hour, which is plenty for one user. If you ever need more, add custom SMTP under **Authentication → Emails → SMTP Settings**.
4. **Recommended after your first sign-in:** go to **Authentication → Sign In / Providers** and turn **Allow new users to sign up** OFF. That stops anyone else from creating an account in your project.

### 4. Site URL and redirect
Open **Authentication → URL Configuration** and set:
- **Site URL**: `https://<github-user>.github.io/lean-loken/`
- **Redirect URLs** → Add: `https://<github-user>.github.io/lean-loken/**` and, for local testing, `http://localhost:8000/**`

OTP codes don't use redirects, but supabase-js checks the site URL anyway, and any email link you ever turn on will need it.

### 5. Deploy the `notify` function in the dashboard editor
1. Run `python3 pwa/build-schedule.py` to make sure `functions/notify/schedule.js` is current.
2. Go to **Edge Functions → Deploy a new function → Via Editor**.
3. Name it **`notify`**. The exact name matters, because it's part of the URL.
4. Replace the editor's `index.ts` with the contents of `functions/notify/index.ts`.
5. Add a second file named **`schedule.js`** (the **+**/"Add file" button in the file list) and paste `functions/notify/schedule.js` into it. The import in `index.ts` is `./schedule.js`, so the file must sit next to `index.ts`.
6. Click **Deploy function**.
7. Open the function's **Details/Settings** and turn **Verify JWT** (also labelled "Enforce JWT verification") **OFF**. Click **Save**.
   The cron call carries only `x-cron-secret`, with no JWT. The function checks auth itself: it accepts the cron secret (compared with the one from Vault), or a valid user JWT for `{test:true}`. Every other POST gets `401`. `GET ?vapid=1` is public.
8. The function URL is `https://ramjgwvkuiylwgxspvyl.supabase.co/functions/v1/notify`.

CLI alternative: `supabase functions deploy notify --no-verify-jwt --project-ref ramjgwvkuiylwgxspvyl`. Don't add any Edge Function secrets. `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` are provided automatically, and `VAPID_SUBJECT` defaults to `mailto:nathanzd@me.com` in code.

### 6. Check it (SQL Editor, optional)
Neither the URL nor the CRON secret needs filling in. The migration already set them (`lean_loken_notify_url`, `lean_loken_cron_secret`).
```sql
select public.ll_invoke_notify();
-- a few seconds later:
select status_code, content::text, error_msg, created
  from net._http_response order by created desc limit 3;
```
You should get `status_code = 200` and JSON like `{"mode":"cron","users":0,"due":0,"sent":0,...}`.

Then open `https://ramjgwvkuiylwgxspvyl.supabase.co/functions/v1/notify?vapid=1` in a browser. It returns `{"publicKey":"B..."}`, and the first call generates and stores the pair. Don't delete the `vapid` row in `ll_config`. A new pair breaks every existing subscription, and each device would have to enable notifications again.

### 7. Turn it on from the phone
1. Install the PWA (open the GitHub Pages URL in Safari → Share → **Add to Home Screen**), open it from the home screen and sign in with the code.
2. In Plan → Notifications, tap **Enable notifications**, then **Send test notification**. You should get "Lean Loken notifications are on".
3. Reminders arrive 15 min before each item, from Mon Oct 12 2026 (the program start) onward.

## How reminders are decided
`dueNotifications()` in `schedule.js` reuses the app's own `timeline()`, `planFor()` and `targetsFor()`. All clock math happens in the time zone stored on the newest `push_subs` row for the user, using `Intl.DateTimeFormat` parts. The server's own zone (UTC) is never used.

| Reminder | When | Skipped if |
|---|---|---|
| Meals (breakfast, snack, lunch, shake, dinner; Sunday food prep) | item time − lead | `checks[id]` is true |
| Training: one notice per block (lift → intervals → walk) | block start − lead | the block's first item is checked |
| Weigh-in | wake − lead | weight is logged |
| Water nudge | 11:00 and 15:00 | logged water ≥ pace (target × the share of the day elapsed, measured from wake to 2 h before bed) |
| Evening log | 20:30 | steps, water and sleep are all logged |
| Wind-down | bed − 30 − lead | `checks.winddown` or `checks.lightsout` is set |
| Caffeine cutoff (off by default) | 14:00 − lead | — |

General rules:
- **Pre-program days** (before `settings.start`, Mon Oct 12 2026) send nothing.
- **Window:** an item is due when its due time falls in (now − 6 min, now]. With a 5-minute cron, every item lands in at least one run. Dedup is a `push_log` insert of `YYYY-MM-DD:itemId` with `on conflict do nothing`, and the function sends only when the insert went through.
- **Settings:** the lead comes from `settings.notifyLead` (default 15, range 0–120). The category switches are `settings.notify = {meals, training, weigh, evening, caffeine}`; all are on except caffeine. `settings.notify.enabled = false` mutes everything.
- **Dead subscriptions:** a push that returns 404 or 410 deletes that `push_subs` row.
- **Payload:** `{title, body, tag, url, data:{url}}`. `url` is relative to the app (`./#today` or `./#train`), so it works under the GitHub Pages subpath.

Debug from the SQL editor (dry run at any instant, without sending or logging anything):
```sql
select net.http_post(
  url := (select decrypted_secret from vault.decrypted_secrets where name = 'lean_loken_notify_url'),
  headers := jsonb_build_object('Content-Type','application/json','x-cron-secret',
             (select decrypted_secret from vault.decrypted_secrets where name = 'lean_loken_cron_secret')),
  body := '{"dry":true,"now":"2026-10-12T23:45:00Z"}'::jsonb);
-- then: select content::text from net._http_response order by created desc limit 1;
```
